# Java 类的加载流程

Java 类的生命周期通常分为 **7 个阶段**：

> **加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载**

本文重点介绍前五个阶段，也就是类从进入虚拟机到完成初始化的过程。

---

## 一、加载（Loading）

### 1. 处理过程

加载阶段首先需要获取类的二进制数据流，例如：
- 从硬盘读取 `.class` 文件；
- 通过文件输入流获取 `byte[]`；
- 从网络、数据库或其他自定义来源获取类文件；
- 交给类加载器进行加载。
类加载器可以是 JDK 提供的内置类加载器，也可以是开发者自定义的类加载器。

### 2. 阶段结果

加载完成后，虚拟机会：
1. 将类的元数据信息加载到方法区；
2. 在堆内存中创建一个代表该类的 `Class` 对象；
3. 建立类的二进制数据与 `Class` 对象之间的关联；
4. 后续可以通过 `Class` 对象和反射机制访问类的信息。

需要注意：

> **同一个 `.class` 文件不一定只对应一个 Class 对象。**

类的唯一性由以下两部分共同决定：

> **类的全限定名 + 加载该类的类加载器**

因此，即使是同一个 `.class` 文件，只要由不同的类加载器加载，也会被虚拟机视为两个不同的类。

### 3. 数组类的特殊性

数组类型不会像普通类一样通过类加载器加载。

例如：

```
User[] users = new User[10];
```

创建数组本身不会触发数组类的加载，数组类型由虚拟机直接创建。

但是，如果数组中存放的是某个对象类型，相关对象类仍然需要按照正常流程加载：

```
users[0] = new User();
```

## 二、验证（Verification）

### 1. 处理过程

验证阶段会对加载后的类进行规范性检查，确保该类符合 Java 虚拟机规范。

因为 `.class` 文件不一定来自 Java 编译器，也可能由 ASM 等字节码工具直接生成，所以虚拟机必须先确认它的合法性。

验证阶段通常包括以下内容：

#### 文件格式验证

- 是否以魔数 `CAFEBABE` 开头；
- 主版本号和次版本号是否被当前 JVM 支持；
- `.class` 文件的各个部分是否完整；
- 常量池中的数据是否合法；
- 文件结构是否符合 Class 文件格式规范。

#### 元数据验证

- 是否符合 Java 语言规范；
- 是否存在非法的继承关系；
- 是否实现了必要的方法；
- 是否覆盖了不允许覆盖的方法。

#### 字节码验证

- 操作数栈和局部变量表的类型是否匹配；
- 跳转指令是否跳转到合法位置；
- 方法调用参数类型是否正确；
- 是否存在危害虚拟机安全的操作。

#### 符号引用验证

- 符号引用对应的类、字段和方法是否存在；
- 当前类是否有权限访问这些成员；
- 引用关系是否符合访问控制规则。

### 2. 阶段结果

验证通过后，虚拟机可以确认：

> **当前类的结构、继承关系、字节码和引用关系基本合法，可以继续进入后续阶段。**

类验证的详细过程可以参考《深入理解 Java 虚拟机》第三版第 268 页。

## 三、准备（Preparation）

### 1. 处理过程

准备阶段主要为类变量，也就是 `static` 修饰的变量分配内存，并设置系统规定的初始值。

例如：

```
public static int count = 10;
public static Object obj = new Object();
```

在准备阶段：

```
count == 0;
obj == null;
```

此时还不会执行代码中的显式赋值操作。

### 2. 阶段结果

准备完成后：

- 类变量已经分配好内存；
- 类变量已经拥有默认值；
- 显式赋值和静态代码块尚未执行。

常见默认值如下：

|类型|默认值|
|---|---|
|`int`、`short`、`byte`、`long`|`0`|
|`float`、`double`|`0.0`|
|`char`|`'\u0000'`|
|`boolean`|`false`|
|引用类型|`null`|

---

## 四、解析（Resolution）

### 1. 处理过程

解析阶段会将常量池中的符号引用转换为直接引用。

例如，字节码中可能只记录了：

```
com/example/User.name
```

这属于符号引用。解析后，虚拟机会将它转换为能够直接定位目标类、字段或方法的引用关系。

需要注意：

> 解析不一定一次性完成。部分符号引用可以在实际使用时再进行延迟解析。

### 2. 阶段结果

解析完成后，相关引用可以直接定位到目标内存区域中的：

- 类；
- 字段；
- 方法；
- 接口。

也就是说，虚拟机已经建立了类与其他类型之间的实际引用关系。

---

## 五、初始化（Initialization）

### 1. 处理过程

初始化阶段是类加载流程中真正执行 Java 代码的阶段。

虚拟机会执行编译器自动生成的：

```
<clinit>
```

方法。

`<clinit>` 方法主要由以下内容合并生成：

- 静态成员变量的显式赋值；
- 静态代码块。

例如：

```
public class Demo {
    private static int count = 10;

    static {
        System.out.println("初始化");
    }
}
```

编译后，静态赋值和静态代码块中的逻辑会被放入 `<clinit>` 方法中，并在初始化阶段执行。

### 2. 阶段结果

初始化完成后：

- 静态变量已经完成显式赋值；
- 静态代码块已经执行；
- 类具备正常使用的运行时状态；
- 类初始化逻辑在 JVM 中只会成功执行一次。

例如：

```
count == 10;
```

此时才是代码中声明的最终值。
