### 一、函数为什么存在？

函数（Function）的核心作用是**把一段 SQL 逻辑打包起来，供反复调用**。它解决的是：

- **复用**：写一次，多处调用，避免重复 SQL。
- **封装**：调用者只需知道输入输出，不必关心内部细节。
- **权限控制**：结合 `SECURITY DEFINER`，可让用户通过函数间接操作无权直接访问的表。
- **减少网络往返**：复杂逻辑在数据库端一次执行完。

函数和事务不是替代关系，而是配合关系：

| 概念 | 解决的问题 | 关键词 |
| :--- | :--- | :--- |
| **事务** | 一组操作要么全成功，要么全失败 | ACID、原子性、一致性 |
| **函数** | 把一组操作打包复用、封装、控权 | 复用、封装、权限 |

> 事务管「数据对不对」，函数管「代码怎么复用」。

### 二、SECURITY DEFINER 是什么？

`SECURITY DEFINER` 是函数的一个安全属性，控制**函数执行时以谁的身份行使权限**。

- **默认：SECURITY INVOKER**  
  函数以**调用者**身份运行。调用者必须自己对函数内部访问的表有权限。

- **指定：SECURITY DEFINER**  
  函数以**创建者**身份运行。即使调用者没有表权限，只要有权执行函数，就能通过函数间接完成操作。

**典型用途**：普通用户不能直接改 `accounts` 表，但可以调用一个 `SECURITY DEFINER` 的转账函数，函数以管理员身份完成扣款、加款、记流水。

### 三、安全风险与注意事项

`SECURITY DEFINER` 本质是“提权”，使用不当会出安全问题。典型攻击是**搜索路径劫持**：函数内写 `SELECT * FROM 敏感表`，恶意用户在自己模式建同名假表，函数以高权限身份运行时可能访问假表。

安全使用必须做三件事：

1. **限制执行权限**  
   创建后默认 `PUBLIC` 可执行，必须 `REVOKE`，再 `GRANT` 给可信用户。

2. **锁定搜索路径**  
   `SET search_path = 可信模式, pg_temp`，且 `pg_temp` 放最后。

3. **显式指定模式名**  
   函数内尽量写全名，如 `admin.敏感表`，避免歧义。
