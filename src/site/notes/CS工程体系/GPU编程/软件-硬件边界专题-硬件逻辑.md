# 软件-硬件边界专题-硬件逻辑（GPU / CUDA）

本篇主侧重点：GPU 向 CUDA 提供哪些执行、访存和同步机制。

软件侧边界见 [[CS工程体系/GPU编程/软件-硬件边界专题-软件逻辑\|软件-硬件边界专题-软件逻辑]]。
硬件主线见 [[CS工程体系/GPU编程/CUDA学习主线-硬件逻辑\|CUDA学习主线-硬件逻辑]]。

## GPU 提供的边界

| 硬件机制 | GPU 提供 | CUDA 使用它表达什么 |
| --- | --- | --- |
| SM 与 Warp 调度 | 持有 Block、选择可发射 Warp、执行线程指令 | Grid、Block、Thread 的并行执行 |
| 寄存器文件 | 为线程保存快速私有状态 | 局部变量、索引和中间结果 |
| 共享内存 / L1 | 提供 SM 内低延迟存储和缓存 | Block 内数据复用 |
| L2 与显存 | 提供跨 SM 的设备内存路径 | 全局内存、常量数据和结果缓冲区 |
| 原子操作 | 对特定地址执行不可分割更新 | 计数器、归约和并发队列 |
| 内存栅栏与同步机制 | 约束可见性或等待条件 | `__syncthreads()`、Fence 和 Stream 依赖 |
| 复制引擎与互连 | 在 Host、Device 和显存间传输 | `cudaMemcpyAsync` 等 API |

CUDA 不会把线程、Block 或业务任务直接存进硬件。
CUDA 把这些概念编译成指令、参数和命令，GPU 再按架构规则执行。

## 例子：共享内存分块

```text
线程从显存加载一部分数据
  → GPU 把数据放入共享内存
  → Block 内线程执行同步
  → 线程重复读取共享数据并计算
  → 结果写回显存
```

加载、存储和同步由硬件执行；分块大小、索引计算和循环结构由 CUDA 代码决定。
