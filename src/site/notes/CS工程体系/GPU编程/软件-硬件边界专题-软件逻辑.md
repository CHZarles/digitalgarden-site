# 软件-硬件边界专题-软件逻辑（GPU / CUDA）

本篇主侧重点：CUDA 如何维护状态，并通过 API 使用 GPU 机制。

硬件提供的机制见 [[CS工程体系/GPU编程/软件-硬件边界专题-硬件逻辑\|软件-硬件边界专题-硬件逻辑]]。
硬件主线见 [[CS工程体系/GPU编程/CUDA学习主线-硬件逻辑\|CUDA学习主线-硬件逻辑]]。
软件主线见 [[CS工程体系/GPU编程/CUDA学习主线-软件逻辑\|CUDA学习主线-软件逻辑]]。

## CUDA 需要回答的四个问题

1. 哪些状态由 Host 代码和 Runtime 维护？
2. 哪个 API、kernel 配置或内存对象会进入 GPU 命令队列？
3. 哪个同步点能证明数据或 kernel 已经完成？
4. 出错时，错误在哪个 API 或哪个异步边界被观察到？

## 软件状态和硬件接口

| CUDA 状态 | 进入硬件的接口 | Host 侧动作 |
| --- | --- | --- |
| Grid / Block / 参数 | Kernel launch 命令 | 计算执行配置并提交 kernel |
| Device 指针 | 设备地址与访存指令 | 分配、传递和释放缓冲区 |
| Stream | 命令队列和依赖 | 排列 kernel、复制和同步关系 |
| Event | 完成记录和查询 | 测量时间、建立依赖和等待 |
| 共享内存大小 | Kernel 资源配置 | 为 Block 申请动态共享内存 |
| 错误状态 | 异步执行结果 | 调用错误查询和同步 API |

## 例子：一次异步向量加法

```text
Host 把输入复制到 Device Stream
  → 在同一个 Stream 提交向量加法 kernel
  → GPU 按 Stream 顺序执行复制和 kernel
  → Host 查询 Event 或同步 Stream
  → Host 确认结果可读，再复制回 Host
```

同一个 Stream 中的顺序关系由 CUDA 建立。
不同 Stream 是否重叠，取决于依赖、设备资源、复制引擎和内存是否满足条件。

## 软件侧原则

- 先区分同步 API、异步 API 和真正的完成点；
- 把 Host 指针、Device 指针和 Unified Memory 的所有权与可见性分开记录；
- 先确认 kernel 的资源需求，再讨论并发 Block 和占用率；
- 每次异步提交后都保留错误检查路径；
- 先沿一条完整路径理解 API，再记零散函数。
