# 软件-硬件边界专题-硬件逻辑

本篇主侧重点：硬件向内核提供哪些机制、状态和事件。

软件侧边界见 [[CS工程体系/操作系统/软件-硬件边界专题-软件逻辑\|软件-硬件边界专题-软件逻辑]]。
硬件主线见 [[CS工程体系/操作系统/操作系统学习主线-硬件逻辑\|操作系统学习主线-硬件逻辑]]。

硬件不理解进程、线程、文件或网络连接这些内核概念。
硬件通过架构规定的接口向内核提供执行机制和事件。

## 硬件提供的边界

硬件向内核提供：

- 指令执行、特权检查和异常入口；
- 地址转换、权限检查和 TLB 失效；
- Cache 一致性、原子指令和内存序；
- MMIO、DMA 和设备队列；
- 中断向量、IPI 和 CPU 状态保存。

## 典型边界

| 机制 | 硬件提供 | 内核维护和使用 |
| --- | --- | --- |
| 指令和特权级 | 执行指令、检查特权、进入异常或系统调用入口 | 定义用户态和内核态的使用规则 |
| 页表和 TLB | 地址转换、权限检查、缺页异常、转换缓存 | 创建地址空间、修改页表、处理缺页 |
| TLB 失效 | 清除指定核心中的转换缓存 | 在映射变化后发起本地和远端失效 |
| Cache 一致性 | 跟踪 Cache line 副本和所有权 | 使用原子指令、锁和内存序 |
| MMIO | 让加载 / 存储访问设备寄存器 | 映射寄存器并按设备协议读写 |
| DMA | 在设备和内存之间传输数据 | 准备缓冲区、描述符和 DMA 地址 |
| 中断 | 接收请求、选择向量、进入 CPU 入口 | 读取设备状态、确认事件、唤醒等待者 |
| IPI | 把请求送到目标核心 | 协调 TLB shootdown、调度和跨核心同步 |

## 例子：写时复制

```text
内核把父子进程的页面映射为只读
  → CPU 执行写指令
  → MMU 检查页表权限
  → CPU 产生缺页或保护异常
  → 内核分配新页并复制数据
  → 内核更新页表并使旧 TLB 项失效
  → CPU 重新执行写指令
```

页表权限检查和异常产生属于硬件。
进程语义、页面复制和映射更新属于内核。

## 例子：设备完成 DMA

```text
内核准备 DMA 缓冲区和描述符
  → 设备控制器执行 DMA
  → 设备控制器记录完成状态
  → 设备通过中断线或消息产生请求
  → CPU 进入硬件定义的中断入口
  → 内核确认状态并回收队列项
  → 内核唤醒等待 I/O 的线程
```

DMA 传输和中断路由属于硬件。
缓冲区所有权、队列状态和线程唤醒属于内核。

## 例子：页表更新

```text
内核写入新的页表项
  → 内核按架构规则执行内存屏障
  → CPU 清除本地 TLB 项
  → 内核通过 IPI 请求其他核心清除对应项
  → 其他核心执行 TLB 失效
  → 内核确认更新完成
```

硬件提供 TLB 失效指令和 IPI 机制。
内核决定何时更新、通知哪些核心以及何时回收旧物理页。

## 硬件侧原则

- 硬件机制决定内核可以使用哪些基础能力。
- 硬件事件通过异常、中断或状态变化进入内核逻辑。
- 硬件不保存进程语义、文件语义或等待队列语义。
- 内核使用的寄存器、页表、队列和描述符必须符合硬件协议。
