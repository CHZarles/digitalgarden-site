# 主题六：fork-硬件逻辑

本篇主侧重点：写时复制依赖的页表权限、地址转换和异常机制。

软件侧见 [[CS工程体系/操作系统/fork-软件逻辑\|fork-软件逻辑]]。

## 硬件支持路径

```text
两个地址空间的页表项暂时指向同一物理页
  → 页表项把共享映射标记为只读
  → 线程执行写指令
  → TLB / MMU 检查写权限
  → 权限不满足，CPU 产生缺页或保护异常
  → CPU 保存架构状态并进入异常入口
```

硬件只知道虚拟地址、页表权限和异常类型。
硬件不理解父进程、子进程或写时复制策略。

## TLB 和 Cache 的影响

建立只读映射后，内核必须处理已经存在的旧 TLB 项。
旧 TLB 项仍可能保存可写权限，因此需要按架构规则失效。
多个核心使用同一地址空间时，需要协调各核心的 TLB。

父子地址空间暂时指向同一物理页时，多个核心也可能缓存该页的副本。
Cache 一致性保证这些副本遵守硬件一致性规则。

## 硬件边界

- 页表权限检查由 MMU 执行；
- 缺页或保护异常由 CPU 产生；
- 状态保存和异常向量由 CPU 架构定义；
- 物理页复制、页表修改和进程语义由内核完成。

## 业务场景

大内存进程执行 `fork` 时，页表权限修改和多核 TLB 失效会产生硬件相关开销。
父子进程频繁写入共享页时，会反复触发异常和 Cache line 传输。
