# 主题十一：I/O 多路复用-硬件逻辑

本篇主侧重点：I/O 多路复用不改变设备的硬件数据路径。

软件侧见 [[CS工程体系/操作系统/io多路复用-软件逻辑\|io多路复用-软件逻辑]]。

## 底层硬件路径

```text
设备
  → 设备控制器
  → DMA 或设备寄存器访问
  → DRAM 中的内核缓冲区
  → 中断或轮询报告状态
  → 内核读取设备状态
```

`select`、`poll` 和 `epoll` 不会增加新的设备控制器、DMA 引擎或中断控制器。
它们只使用内核已经获得的设备、文件或网络状态。

## 硬件边界

- 网卡仍然通过 DMA 写入接收缓冲区；
- 存储设备仍然通过队列和 DMA 完成读写；
- 设备仍然可以使用中断、轮询或中断合并；
- 多路复用只改变线程等待和事件分发方式。

## 业务场景

一个线程等待大量网络连接时，硬件请求数量不因此减少。
设备仍然执行原有的 DMA、寄存器访问和中断或轮询路径。
