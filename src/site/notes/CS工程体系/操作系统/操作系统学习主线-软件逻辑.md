# 操作系统学习主线-软件逻辑

> **从硬件提供的机制出发，学习内核如何组织状态、配置硬件和处理事件。**

这条主线关注操作系统的软件行为。
它和 [[CS工程体系/操作系统/操作系统学习主线-硬件逻辑\|操作系统学习主线-硬件逻辑]] 使用同一组硬件事实，但观察角度不同。

- 硬件逻辑问：硬件如何转换地址、传输数据和改变控制流？
- 软件逻辑问：内核维护什么状态，怎样使用这些硬件机制？
- 业务场景问：这些机制怎样影响延迟、吞吐和并发？

## 软件和硬件的共同边界

硬件和内核通过少量稳定机制连接：

- 指令集和特权级；
- 页表、TLB 和地址空间根；
- MMIO 寄存器和设备队列；
- DMA 地址、缓冲区和描述符；
- 中断向量、异常入口和 IPI；
- 原子指令、缓存一致性和内存序。

硬件专题解释这些机制怎样工作。
软件专题解释内核怎样配置、维护和使用这些机制。
边界的完整说明见 [[CS工程体系/操作系统/软件-硬件边界专题-软件逻辑\|软件-硬件边界专题-软件逻辑]]。

## 软件主线的共同路径

```text
线程运行
  → 执行普通指令或发起系统调用
  → CPU 进入内核入口，或内核访问硬件寄存器
  → 内核修改页表、设备队列或等待队列
  → 硬件执行地址转换、数据传输或产生事件
  → 内核处理异常、中断或完成状态
  → 唤醒等待者并重新调度
  → 线程继续运行
```

这条路径是学习索引。
每个专题只展开自己负责的状态和动作。

每个主题分别提供硬件逻辑文件和软件逻辑文件。
两份文件通过边界说明和交叉链接保持连接。

## 软件主线图

```mermaid
flowchart TB
    T[运行中的线程] --> ENTRY[系统调用、异常或中断入口]
    ENTRY --> DISPATCH[内核分发路径]
    DISPATCH --> PROC[进程和线程状态]
    DISPATCH --> VM[地址空间、页表和 TLB 状态]
    DISPATCH --> IO[设备队列、DMA 和文件状态]
    DISPATCH --> SYNC[锁、等待队列和同步状态]

    VM --> HW[硬件执行地址转换]
    IO --> HW2[硬件执行数据传输]
    HW --> EVENT[异常或权限事件]
    HW2 --> EVENT2[完成状态或中断]
    EVENT --> ENTRY
    EVENT2 --> ENTRY

    SYNC --> SLEEP[线程阻塞或睡眠]
    EVENT2 --> WAKE[唤醒等待线程]
    WAKE --> RUNQ[加入可运行队列]
    PROC --> SCHED[调度器选择线程]
    RUNQ --> SCHED
    SLEEP --> SCHED
    SCHED --> T
```

这张图描述内核代码的共同闭环：进入内核、读取或修改状态、配置硬件、等待事件、唤醒线程和重新调度。
每个专题只展开其中一段闭环。

## 当前已有专题的侧重点

同一个主题可以同时出现在硬件主线和软件主线。
两条主线引用同一主题时，侧重点不同：

| 主题 | 硬件逻辑侧重点 | 软件逻辑侧重点 |
| --- | --- | --- |
| `fork` | 页表权限、缺页异常、TLB 和物理页访问 | 进程创建、COW 映射、异常处理和进程状态 |
| 页表更新 | TLB 项失效和跨核心通知 | 页表修改顺序、shootdown 协议和安全回收 |
| 中断 | 中断源、控制器、向量和 CPU 控制流 | 入口代码、设备状态确认、事件分发和唤醒 |
| I/O | MMIO、DMA、设备链路和中断 | 驱动状态、队列、缓冲区和等待者 |
| 多核 | 一致性、原子指令和内存序 | 锁、调度、并发数据结构和内核同步 |
