## 00 基础概念

### Authentication

确认访问主体是谁。

### Authorization

确认访问主体可以执行什么操作。

### Principal / Subject

系统中的访问主体，可以是：

- 用户
- 服务
- 设备
- 应用程序

### account_id

业务系统中的账户标识。

```
外部身份
  ↓
Principal / Subject
  ↓
account_id
  ↓
业务数据与权限
```

## 01 凭证与令牌

### Session Cookie

- 典型场景：传统 Web 应用
- 浏览器自动携带 Cookie
- 服务端保存 Session 状态

### Access Token

- 典型场景：API 访问
- 生命周期较短
- 用于访问 Resource Server

### Refresh Token

- 用于换取新的 Access Token
- 生命周期较长
- 需要更严格的保护

### API Key

- 典型场景：开发者、脚本、简单服务调用
- 通常不表示具体用户登录
- 需要支持轮换和撤销

### 凭证类型对比

|类型|典型场景|状态保存位置|
|---|---|---|
|Session Cookie|Web 登录|服务端|
|Access Token|API 调用|Token 或授权服务|
|Refresh Token|续期|授权服务|
|API Key|开发者或服务调用|服务端|

## 02 OAuth / OIDC 用户登录

### OAuth 角色

#### Authorization Server

负责：

- 用户登录
- 用户授权
- 签发 Token

#### Resource Server

负责：

- 提供受保护资源
- 验证 Access Token
- 执行权限判断

#### OAuth Client

负责：

- 发起登录
- 接收 Authorization Code
- 换取 Token
- 调用 Resource Server

### OAuth 授权码流程

```
用户访问 Client
  ↓
Client 重定向到 Authorization Server
  ↓
用户登录并授权
  ↓
Authorization Server 返回 Authorization Code
  ↓
Client 使用 Code + PKCE 换取 Token
  ↓
Client 使用 Access Token 调用 Resource Server
```

### PKCE

保护 Authorization Code，防止 Code 被拦截后滥用。

### state

- 防止 CSRF
- 关联登录请求和回调请求

### nonce

- 用于 OIDC
- 防止重放
- 关联 ID Token 与原始登录请求

### redirect_uri

OAuth 登录完成后的回调地址。

要求：

- 必须预先登记
- 必须严格匹配
- 避免开放重定向

### scope

请求的权限范围。

```
openid profile email
```

### audience

Token 面向的资源服务器。

### issuer

Token 的签发者。

### ID Token

- OIDC 身份令牌
- 用于说明用户是谁
- 不用于调用业务 API

### Access Token

- 用于访问资源
- 表示当前请求具备哪些访问权限

### OAuth 2.0 / 2.1

统一学习为：

> OAuth 2.x 与现代安全实践

不单独展开版本差异。

### JWT

常见的 Token 格式，包含：

- Header
- Payload
- Signature

### JWS

表示带数字签名的内容，用于验证 Token 完整性。

### JWK / JWKS

- JWK：一把 JSON 格式的公钥
- JWKS：多把 JWK 组成的公钥集合
- 用于 JWT 验签

```
JWT
└── JWS 签名
    └── JWK / JWKS 公钥验证
```

## 03 API Key

### API Key Authentication

客户端在请求中携带 API Key，服务端验证其有效性。

### API Key Hashing

服务端不保存 API Key 明文，只保存 Hash。

```
明文 API Key
  ↓
Hash
  ↓
服务端保存 Hash
```

### Credential Rotation

定期或在泄露后更换凭证。

### Credential Revocation

主动吊销凭证。

### API Key Leak Prevention

- 不写入日志
- 不提交到代码仓库
- 不放在前端代码中
- 泄露后立即撤销

### Secret Shown Once

API Key 明文只在创建时展示一次。

> 实现细节，不作为独立核心概念。

## 04 服务间鉴权

### Service Identity

服务本身也是一种访问主体。

```
User Identity
Service Identity
Device Identity
        ↓
Principal
```

### Service-to-Service Auth

服务之间不依赖用户登录，而使用服务自身身份完成鉴权。

### Client Credentials Grant

服务使用自己的 Client ID 和 Secret 获取 Access Token。

### HMAC 请求签名

使用共享密钥对请求内容生成签名。

```
请求内容 + 时间戳 + 密钥
  ↓
HMAC
  ↓
Request Signature
```

#### Canonical Request

将请求方法、路径、参数、Body 等按固定规则规范化后再签名。

#### HMAC-SHA256

HMAC 使用 SHA-256 作为摘要算法的一种实现方式。

### Replay Attack

攻击者重复发送已经截获的合法请求。

### Timestamp Verification

通过时间戳限制请求有效期，降低重放风险。

可结合：

- Nonce
- Request ID
- 服务端去重记录

### Key Rotation

定期更换服务间共享密钥。

## 05 高级机制

### Token Introspection

Resource Server 向 Authorization Server 在线查询 Token 状态。

适用于：

- Opaque Token
- 集中式 Token 校验
- 需要实时失效控制的场景

### Token Revocation

主动使 Token 失效。

适用于：

- 长期 Token
- 退出登录
- 安全事件处理

### mTLS

通过双向 TLS 证书验证服务身份。

适用于：

- 高安全等级内部网络
- 零信任网络
- 已具备证书基础设施的环境

## 06 MCP 鉴权

### Model Context Protocol

用于模型访问工具、资源和远程服务的协议。

### Remote MCP Server

部署在远程网络上的 MCP 服务。

### MCP OAuth Protected Resource

远程 MCP Server 可以使用 OAuth 2.x 保护工具调用接口。

### MCP OAuth 调用流程

```
客户端
  ↓
OIDC 登录
  ↓
获取 Access Token
  ↓
携带 Access Token 调用 Remote MCP Server
  ↓
访问受保护的 MCP 工具
```
