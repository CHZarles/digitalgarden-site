``` mermaid

stateDiagram-v2

direction TB

  

[*] --> 状态1_明文暴露态: 发起 TCP 连接

  

state "1. 明文暴露态 (无加密 / 无身份)" as 状态1_明文暴露态 {

[*] --> 交换临时公钥: ClientHello & ServerHello (附带各自临时公钥)

交换临时公钥 --> 算出共享秘密: 各自用[自身临时私钥 + 对方临时公钥]本地做 ECDHE 计算

算出共享秘密 --> 派生第一批密钥: 将[共享秘密(种子)]输入 HKDF 加工厂

派生第一批密钥 --> [*]: 产出【握手密钥】与【校验密钥】

}

  

状态1_明文暴露态 --> 状态2_握手加密态: 启用【握手密钥】锁住信道 (解决窃听与前向安全)

  

state "2. 握手加密态 (已加密 / 待验真身)" as 状态2_握手加密态 {

[*] --> 查验CA证书: 服务端发证书 -> 客户端用根证书验签，提取[身份公钥]

查验CA证书 --> 查验实时签名: 服务端用[身份私钥]对握手记录签名 -> 客户端用[身份公钥]验签

查验实时签名 --> [*]: 确认对方持有私钥，非中间人转发证书

}

  

状态2_握手加密态 --> 异常熔断态: 证书无效 / 签名伪造

状态2_握手加密态 --> 状态3_历史对账态: 身份验证通过 (解决中间人伪装)

  

state "3. 历史对账态 (已认证 / 待验完整性)" as 状态3_历史对账态 {

[*] --> 互发Finished消息: 双方用【校验密钥】对从头至今所有握手报文算 HMAC

互发Finished消息 --> [*]: 双方比对校验值，确认明文协商阶段未被篡改/降级

}

  

状态3_历史对账态 --> 异常熔断态: Finished 校验值不匹配 (遭遇篡改/降级攻击)

状态3_历史对账态 --> 状态4_业务安全传输态: 对账一致，用 HKDF 派生第二批密钥【应用密钥】

  

state "4. 业务安全传输态 (控制面与数据面隔离)" as 状态4_业务安全传输态 {

[*] --> 读写分离加密: 废弃握手密钥，换用读写独立的【应用密钥】+ AEAD 算法传输 HTTP

}

  

state "连接立即中断 (Alert)" as 异常熔断态

异常熔断态 --> [*]


```
